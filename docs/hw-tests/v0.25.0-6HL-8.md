# 0.25.0-6HL-8: what to try

The fork's line on upstream 0.25.0 with listen-first roaming, the
settings store and the menu merged upstream, the rest of the UI stack
(home screen, microphone gain, frequency offset), the loader, the test
tools and the fork's features. Against 0.25.0-6HL-7-pr56 the menu is the
second round of the menu review, and Auto Roaming is the codeplug's
switch.

## What changed, against 6HL-7-pr56

| 6HL-7-pr56 | 6HL-8 |
| --- | --- |
| Roaming: Status, Roaming On/Off (for the session), Roam zone | Roaming: Automatic (the codeplug's Auto Roaming, kept there), Status, Roam zone; no Roaming Off |
| `roam auto on\|off` until the next restart | `roam auto on\|off` sets the codeplug's Auto Roaming, as the Automatic row |
| GPS: Status, Receiver; Settings > GPS: Satellites | GPS: Enabled, Status, Satellites; no Settings > GPS |
| Display: Brightness, Light time | Display: Brightness, Light time, Help text (Off hides the panel under the lists) |
| Settings: Home screen, Audio, Radio, Keys & battery, Clock, GPS, APRS | Settings: Home screen, Audio, Radio, Keys, Battery, Clock, APRS |
| Home screen: Preset and the six rows | Also Up/Down: Zone, Channel or Off (what Up and Down do on the home screen) |
| Simple preset: the contact large, talkgroup, last caller | Simple: the clock, the channel's name large, its frequency and the power, nothing else |
| Next to power: Voltage, Volume, Signal | Also None |
| Tools: Codeplug, Activity, Log, Key test, Version | Tools: Codeplug, Activity, Log, Version; the key test only in debug builds |
| Menu opens a row | A digit 1 to 9 opens the row at that place too |
| A value screen sets the value with Menu | Squelch, squelch type, brightness, time zone and the frequency offset take effect while chosen; Menu keeps, Exit puts the old value back |
| Squelch type: Carrier, Tone | Carrier, CTCSS/DCS |
| The `#` hint: `# VFO` | `# MEM` in the VFO, `# VFO` on a memory channel |
| Roaming status: positions and levels | The repeaters by name, a pointer at the one in use; the reason a channel does not roam |

With Auto Roaming off, PTT still searches for a repeater when the one in
use does not answer, and the roam key searches as before; only the
listening to other repeaters and the moves between calls need it on.

## The preferences record

The shared fields moved when the roaming byte left the record: field
bytes 0 to 5 the home screen, 6 the help text, 7 Up/Down, 8 and 9 the
microphone gains, 10 and 11 the frequency offset. The fork's fields stay
from field byte 64 (64 clock in UTC, 65 APRS receive, 66 packets heard
in APRS mode, 67 the dedicated mode) and read as before.

A record written by 6HL-7-pr56 is read one field off: the home screen
rows take their neighbours' values, the help text takes the old bottom
row (usually Off), the DMR microphone gain takes the old FM one, the FM
gain follows the codeplug, and the frequency offset reads about -250 Hz
where it was +2 kHz. After the first start set again: Settings > Radio >
Freq offset (+2000 Hz on this radio), Settings > Home screen > Preset
(then any row), Up/Down, Settings > Audio (both gains), and Display >
Help text. The first change writes a record in the new layout.

## Before

- `dmm-radio` from this build's folder; `dmm-radio update
  0.25.0-6HL-8.bin --try`, then `dmm-radio confirm` before any runner
  checklist that restarts the radio.
- After the first start: `baseband: running` in the start-up lines;
  `settings` shows the `preferences record:` and `preferences (fork):`
  lines; `fm status` the offset.
- For tests without transmitting: Menu > Roaming > Automatic Off (or
  `roam auto off`); it is kept in the codeplug, so put it back after.

## 1. The stack's checklists (runner)

None of these transmit without `--allow-transmit`; the QDMR round trips
are skipped without `--allow-qdmr-write`.

```sh
R=tools/radio_test/radio_test.py
$R run menu --no-human --out runs/menu
$R run home-screen --no-human --param dmr="<zone>/<DMR channel>" --param roam="<zone>/<roaming channel>" --param fm="<zone>/<FM channel>" --out runs/home
$R run settings-storage --no-human --out runs/settings
$R run mic-gain --no-human --out runs/mic-gain
$R run frequency-offset --no-human --out runs/offset
$R run loader --no-human --out runs/loader
$R run test-tools --no-human --out runs/test-tools
```

The menu checklist finds its number keys by the rows' names, so the
fork's extra rows do not move it. On the simulator the frequency offset
checklist fails where it expects 0 Hz after a start: the fork starts at
+2 kHz.

## 2. The fork's checklists (console and keys)

Skip every step that transmits.

| Checklist | Steps | Skip |
| --- | --- | --- |
| `activity.md` | 1-5, 7, 10 | 6 (`roam now` wakes repeaters), 8-9 (transmit) |
| `rtc-calibration.md` | all; part 2 needs a GPS fix | - |
| `plug-editor.md` | 1-6 (console), 1-20 (keys), on a test channel | 7-8 (need a PC write: optional) |
| `aprs.md` | 8, 9, 10 | 2, 3 (beacons), 6-7 (second radio transmits) |
| `aprs-rx.md` | 1-3, 5-10 | 4 (`aprs send`) |
| `aprs-mode.md` | 1-13, 17-26 | 14 (`key ptt`), 15 (`ptt 500`), 16 (`aprs every 60`) |
| `audio-probe.md`, `aprs-board-link.md` | all | - |

Where a step counts keys, the number keys reach the same rows: the top
is Channel 1, Roaming 2, GPS 3, APRS 4, Display 5, Settings 6, Tools 7;
Settings holds Home screen 1, Audio 2, Radio 3, Keys 4, Battery 5,
Clock 6, APRS 7; Tools holds Codeplug 1, Activity 2, Log 3, Version 4.
So Settings > Clock is Menu, 6, 6; Settings > APRS > Hear packets is
Menu, 6, 7, 3; Tools > Activity is Menu, 7, 2. The Tools panel reads
"Codeplug, activity, the log and the version" (with the key test in
debug builds).
