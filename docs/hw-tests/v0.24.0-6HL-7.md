# 0.24.0-6HL-7: what to try

The fork's line rebuilt on the upstream UI stack: upstream `main`, the
open pull requests (settings store, menu, home screen, microphone gain,
frequency offset, write stall, loader), the test tools, and the fork's
features ported onto the stack's menu, home screen and preferences
record. The fork's own menu, standby screen and preferences record
(`DMMP`) are gone.

The status bar's beacon mark is a blue `APRS` tag, as before.

## The preferences record

The record is upstream's `DMMR`: the shared fields first, then this
fork's from field byte 64 (`docs/settings-storage.md`, "This fork's
fields"): 64 clock in UTC, 65 APRS receive, 66 packets heard in APRS
mode, 67 the dedicated mode; 68 to 79 free. An upstream-shaped image reads
the shared fields of such a record and drops the fork's when it next
writes it.

The first start after 6HL-6 finds 6HL-6's `DMMP` record, which this build
does not read: every preference takes its default. That is: roaming on,
the Detailed home screen, the microphone gains from the codeplug, the
frequency offset +2 kHz (this fork's default), clock in local time, APRS
receive on, packets quiet, APRS mode off. The first change in the menu
writes a `DMMR` record over it. Set again whatever 6HL-6 had otherwise
(a home screen layout, clock in UTC, APRS mode).

## 1. The stack's checklists (runner)

None of these transmit without `--allow-transmit`; the QDMR round trips
are skipped without `--allow-qdmr-write`.

```sh
R=tools/radio_test/radio_test.py
$R run menu --no-human --out runs/menu
$R run home-screen --no-human --param dmr="<zone>/<DMR channel>" --param roam="<zone>/<roaming channel>" --param fm="<zone>/<FM channel>" --out runs/home
$R run settings-storage --no-human --out runs/settings
$R run mic-gain --no-human --out runs/mic-gain
$R run frequency-offset --no-human --out runs/offset
$R run write-stall --no-human --out runs/write-stall
$R run loader --no-human --out runs/loader
$R run test-tools --no-human --out runs/test-tools
```

The menu checklist takes the fork's extra rows (APRS at the top, Codeplug
and Activity in Tools). The frequency offset checklist sets 0 Hz and
puts the offset back at the end; on the simulator, whose codeplug does
not survive its restart, it shows this fork's +2 kHz default instead.
