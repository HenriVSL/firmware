# v0.5.0: crash capture and the debug console

The log now starts with why the previous run ended, and the log port takes
a few typed commands. The crash record lives in RAM that the vendor boot
loader might also use; these steps show whether it survives a restart.

## Before you start

- v0.4.0 passed on this radio.
- A terminal on the log port as in v0.4.0. Commands are typed blind (no
  echo) and end with Enter.

## Steps

| # | Do | Expect |
| --- | --- | --- |
| 1 | Flash, power on, open the log port | `last reset: power-on (flags 0c000000)` or similar, no `crash:` line |
| 2 | Type `help` | `> help` and the list of commands |
| 3 | Type `restart` | The radio restarts (red flash). Reopen the port: `last reset: software`, no `crash:` line |
| 4 | Type `fault` | `crashing on purpose`, then a restart. Reopen: `last reset: software` and two `crash:` lines, the first `crash: test fault in task link, detail 3, pc 0800...` |
| 5 | Type `hang` | `watchdog no longer fed`, the green heartbeat keeps going, and within about 2-4 s the radio restarts. Reopen: `last reset: watchdog` |
| 6 | Power off with the knob, power on | `last reset: power-on`, no `crash:` line |
| 7 | Repeat step 4, then power off and on before opening the port | `last reset: power-on`; a `crash:` line may or may not still be there (RAM may keep its contents for a moment) |
| 8 | Flash factory V3.06 back as in v0.3.0 | The factory firmware works |

## If something is off

- Step 4 shows `last reset: software` but no `crash:` line: the boot loader
  overwrites the crash record. Note the flags value and report it.
- Step 4 or 5 shows `last reset: unknown (flags 00000000)`: the boot loader
  clears the reset flags. Report it; the crash lines still work.
- Step 5 never restarts: the watchdog is not running. Power off with the
  knob and report it.

## Report back

- The `last reset:` and `crash:` lines from steps 1, 3, 4, 5 and 6, copied
  as they are.
