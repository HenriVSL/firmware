# v0.18.0: Board facts out of shared code

Radio-, chip- and board-specific code moved out of the shared folders.
Calibration, codeplug and data flash are read through model-named
classes, the baseband's codec set-up comes from the board, and each chip
service runs its own console commands. Keys have generic names; the board
gives their on-screen labels. Behaviour should be as in 0.17.2, except
that the log names keys generically.

The radio task's stack grew from 2 KB to 3 KB: the first build of this
release overran it and restarted a few seconds after start-up. Log lines
in the deepest set-up code now use their own small helpers, which saves
stack. The uptime line every 10 s lists the unused stack words of every
task. The codec trims now go in when the baseband starts, and the FM
chip's pin register is logged again (as debug lines).

Parts with one implementation per radio (FM transceiver, baseband,
calibration, input, battery sense, data port) are now chosen at build
time instead of through virtual calls; behaviour should not change.

## Before you start

- 0.17.2 on the radio works as expected, for comparison.
- An FM channel with a station to talk to, and the USB log open.

## Steps

| # | Do | Expect |
| --- | --- | --- |
| 1 | Flash; watch the start screen and log | "DeltaMM 0.18.0"; log shows `calibration: copy A, battery offset ...` (or copy B), `D fm: started, pin register ... -> ...` and `codeplug: zone ...`; no `crash:` line |
| 2 | Leave the radio on standby for 2 minutes | No restart; an uptime line every 10 s ending `unused stack words: ...` with six tasks (`input`, `audio`, `system`, `ui`, `link`, `radio`), each above 50 |
| 3 | Switch off, switch on, wait 1 minute | Log shows `last reset: power-on` and no `crash:` line; no restart |
| 4 | Look at the battery bars | Same as on 0.17.2 |
| 5 | Turn the volume knob from bottom to top on a busy channel | Silent at the bottom, steps up evenly, as loud at the top as on 0.17.2 |
| 6 | Receive a station | Audio at the same level and quality as on 0.17.2; the log's `squelch open` line ends with RSSI, noise and quality |
| 7 | PTT and talk | The other station hears clear audio at normal loudness |
| 8 | Step through every channel of the zone and back with the knob, then change zone with P1 and VFO with # | No restart; each channel receives |
| 9 | Console `mic on`, then `mic off` | `D fm: microphone on, pin register ... -> ...`, then `microphone muted ...`; the two values differ only in the `00c0` bits, both set when muted |
| 10 | Console `help` | Two extra lines: `FM chip: ...` and `baseband chip: ...` |
| 11 | Console `fm 1f`, then `fm status` | The register's value; then frequency, carrier, speaker, RSSI, noise, quality |
| 12 | While receiving: `fm tune 0`, then `fm tune auto` | Reception drops at 0, comes back at auto (log says "calibrated") |
| 13 | While receiving: `fm sweep` | A `tune ...` line per step, then `sweep: strongest ...`; no restart |
| 14 | Console `bbtone 1000 500` | A 1 kHz tone as loud as on 0.17.2 |
| 15 | Console `bb packet 20 30` | Log shows a reply with the baseband's product name |
| 16 | Console `codec 1 10 17` | `unknown command` (the old name); `bb codec 1 10 17` works instead |
| 17 | Look at the standby screen's bottom bar | `Menu  P1 Zone  P2 Chan  # VFO` as before |
| 18 | Console `keytest`; press P1, P2, PF1, PF2, PF3, PTT | Boxes labelled as on the radio light up; log says `key Front1 pressed`, `Front2`, `Side1`, `Side2`, `Side3`, `PTT` |
| 19 | Lock (hold *); press P1 and PF1 | Both refused as on 0.17.2 |
| 20 | Read the latest uptime line after all steps | Every task still above 50 unused stack words |
