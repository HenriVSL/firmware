# 0.24.0-6HL-1: what to try

A trial build from the `trial` branch: `plug-edit` (the codeplug editor,
`prog watch`) plus the fixes made for the open pull requests, and the
console test tools. This page
lists everything waiting for a run on the radio, in a sensible order;
each item names the checklist that holds its steps.

## Before you start

- A verified backup (`dmm-radio check-backup`) and the codeplug saved with
  QDMR.
- `dmm-radio` from this build: the radio now shows the factory USB IDs,
  and older `dmm-radio` builds take it for a radio on its factory
  firmware.
- The log port open (`scripts/watchlog.py` finds it by name, as before).

## 0. Test tools

The console's `key <name> [long]` and `knob <steps>` work the UI, and
`screen shot` / `screen watch <s>` stream the screen's drawing (see
6HL-20 above). With them most UI steps below run from the PC.

## 1. Flash and the new USB identity

| # | Do | Expect |
| --- | --- | --- |
| 1 | Flash this build | It starts; the new USB identity as below |
| 2 | `lsusb -d 28e9:018a -v`, `dmm-radio ports` | Serial `DeltaMM`; two ports, "DeltaMM data" and "DeltaMM log"; `dmm-radio ports` lists both as DeltaMM, none as factory firmware |
| 3 | An unchanged QDMR: `dmrconf detect`, then a read on the data port | Found as a D878UVII; the read as in `programming.md` step 2 |
| 4 | The qdmr fork (its new detection, not committed yet) | Only the data port is tried; read and write work |
| 5 | The CPS under Wine | Unchanged: it uses the mapped COM port |
| 6 | `dmm-radio flash --wait` with this build again | The radio running DeltaMM is not taken for one in update mode; after the switch to update mode the flash goes through |

Steps 8 and 9 of `programming.md` hold the same checks for the pull
request.

## 2. Codeplug editor (first run)

`plug-editor.md`, all 15 steps, then the stack: every task above 50
unused stack words in the latest uptime line. Test channel #16 may be
changed freely.

New in 6HL-14: most fields have names. Look through each book's pages
(P1/P2): a channel has Basic, DMR, FM and APRS pages; Settings has Radio,
Display, Audio, DMR, Boot, Keys and Roaming; APRS has Receive, Fixed and
More freqs. Check that the values match what QDMR shows for the same
codeplug, and that key functions show by name (PF3: Roam).

## 3. Menu and screens

`menu.md` and `screens.md`: the menu drawn in place (no flashing), Up
raises and Down lowers a value, the battery icon.

## 4. APRS

`aprs.md` step 10: with the APRS frequency cleared in the codeplug, no
beacon goes out and the radio says `No APRS frequency`. Put the
frequency back afterwards. Steps 1 and 2 again with it back in place.

## 5. Roaming

From `roaming.md`:

- Steps 4 to 9, 13 and 14 (still open in the pull request).
- Step 25 (new in 6HL-15 and 6HL-16): after a restart, automatic searches back off to 2 minutes instead of every minute, and the hotspot's beacon period (60 s) is learned from its first two beacons, within about 3 minutes.
- With a carrier alone no longer counting as the repeater heard: step 9
  (automatic search after the quiet time) and step 21 (repeater off:
  misses, then searches).
- Beacon timing for any period and length: steps 18, 19, 21 and 22 with
  the hotspot's usual beacons (60 s, 3 s), then again with long ones,
  such as every 120 s for 8 s. Expect each beacon taken (`beacon of
  repeater N, ... ms` up to 16.5 s), the period learned as 120 s, and
  Roam status keeping the level fresh between beacons. Sweeps may take
  longer to find a 120 s repeater the first time.

## 6. Field names against a real write

Mostly done without the radio (see `docs/plug-edit-status.md`). To check
one on the radio: change a setting in QDMR, write, and read what
`prog watch on` logged.

Five settings QDMR does not write for this radio need the factory CPS:
power save, VOX level, VOX delay, VOX source and max headphone volume.
With the logger running, read the radio in the CPS, change one of them,
write, and repeat for each. Expected in the log: bytes 0x0B, 0x0C, 0x0D,
0x33 and 0x52 of the general settings (0x02500000 + offset), one per
round.

## 7. Settings kept in the codeplug

Menu changes are saved about 3 s after the last one: settings with a
place in the codeplug go there, DeltaMM's own (frequency offset, home
screen, UTC clock, APRS receive) into DeltaMM's record. Roaming off lasts
only until a restart.

| # | Do | Expect |
| --- | --- | --- |
| 1 | Flash | No codeplug write at start; a read is identical to the one before |
| 2 | Change squelch, light, light time, battery save and time zone; restart | All kept; the log says `settings kept in the codeplug` about 3 s after the last change |
| 3 | Change the offset, UTC clock and APRS receive; restart | All kept |
| 4 | Change a channel's power and squelch type, then the zone and channel; restart | The radio starts on that channel with that power; other channels unchanged |
| 5 | Read with QDMR and compare with the read from step 1 | Only the changed values differ |
| 6 | Write the codeplug with QDMR, restart | DeltaMM's own settings are still there |
| 7 | Turn roaming off, restart | Roaming on again |
| 8 | Change a setting and start a QDMR write within 3 s, a few times | No hang: the save goes first and the write waits, or the write goes first |

## 8. Home screen

Menu > Settings > Home screen sets what each row shows. `screen.py shot` takes the
pictures; `screen.py watch` checks for flicker.

| # | Do | Expect |
| --- | --- | --- |
| 1 | Menu > Settings > Home screen | First in Settings; seven rows, Preset first; titles not cut (`Preset`, `Bottom row` alone when the group name does not fit) |
| 2 | Preset Simple, back to the home screen | No top line; the contact large, `TG n` and its name under it; `No call heard yet` at the bottom |
| 3 | Preset Roaming | A signal meter under the name, bars and the level in dBm |
| 4 | Preset Detailed | As before this build |
| 5 | Top row Number, Next to power Volume, Bottom row Position | `CH n/m` top left; `VOL n`; `No GPS position` without a fix, the position with one; Preset shows `Own` |
| 6 | Restart | The layout kept |
| 7 | Bottom row Last caller, then a call heard | `Last: <name>  now`, a minute later `1 min ago` |
| 8 | Clock Off, Top row None, Big name Zone, Next to power Signal | No top line or clock; the zone name large; `SIG` and the level next to the power |
| 9 | `screen.py watch 20` with the meter showing | No flicker or blinks; the meter and voltage redrawn only when their value changes, the battery icon only when its fill changes |
| 10 | Set your own layout back | Kept after a restart |

## 9. The menu: operating first, then Settings and Tools

`menu.md` holds the full steps. In short:

| # | Do | Expect |
| --- | --- | --- |
| 1 | Menu | `Menu 1/6`: Channel, Roaming, GPS, APRS, Settings, Tools |
| 2 | Each of Channel, Roaming, GPS and APRS | Channel: Squelch, Squelch type, Power. Roaming: Status, Roaming, Roam zone. GPS: Status, Receiver. APRS: Send now, Auto send, Heard stations |
| 3 | Settings | Home screen, Display, Keys & battery, Clock, GPS, APRS, Radio; each opens its group, titled `Settings > ...` where it fits |
| 4 | Settings > Display, change Brightness, Exit, Exit | Back in Settings on Display, then in the top menu on Settings; the brightness kept after a restart |
| 5 | Settings > Radio | Freq offset, as before |
| 6 | Tools > Codeplug editor, a book, Exit back out | Back in the editor's list, then Tools on Codeplug editor |
| 7 | APRS > Heard stations, Exit | The heard list; Exit returns to APRS. From P2 the heard list's Exit still goes to standby |
| 8 | APRS > Send now (with a GPS fix) | `Position queued`, then `Beacon sent` |
| 9 | GPS > Status, Exit | The GPS screen; Exit returns to GPS |
